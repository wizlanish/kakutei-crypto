# ROADMAP — やり残しと次の一手

上から順に優先度が高い。着手したら該当行を更新し、終わったら「完了」に移す。

## P0 — 正しさに関わる（先にやる）

- [ ] **手数料が数量に含まれるかの検証。** 約定のある実ファイル（OKJ「取引口座履歴」、手数料の発生した Coincheck 様式1）で、
      「数量は手数料と別」という前提（CLAUDE.md §6）が正しいかを確かめる。違っていたらパーサーを直し、テストを足す。
- [ ] **OKJ「取引口座履歴」パーサー。** 注文履歴には手数料も約定時刻もない（注文時刻だけ）。取引口座履歴に対応すれば、
      手数料が必要経費・取得価額に入り、年末をまたぐ指値注文の年の判定も正しくなる。
- [ ] **後の年の opening が二重計上になりうる。** 前年分のファイルも取り込んだうえで opening 行も足すと、年始残高が二重になる。
      同じ銘柄の取引より後に opening がある場合は check で警告する。
- [ ] **reward / fork / opening 行の円手数料が無視される。** 経費にするか、警告を出す。

## P1 — 使い勝手・堅牢性

- [ ] CSV のヘッダーに空白があるとパーサーが KeyError で落ちる（`read_rows` で DictReader の fieldnames を strip する）。
- [ ] 送付と受取の突き合わせが貪欲法なので、正しい組み合わせを見逃すことがある（数量と時刻が最も近いものを優先する）。
      複数の台帳を渡したとき、送付が時系列順に並んでいない点も直す。
- [ ] 終了コードの整理。計算対象の年にデータがないとき（`--year 2030`）の案内。
- [ ] Coincheck の報酬判定キーワード（`coincheck.py` の `_REWARD_WORDS`）を実データで確かめる。
      spec §4.4 の記載（「受取」を含む）とコードが違うので、どちらかに揃える。
- [ ] テストの穴: 売った通貨で払った手数料つきの sell、受け取った通貨で引かれる手数料つきの swap、
      OKJ 形式の CRLF・BOM、移動平均法の年またぎ。

## P2 — 機能追加

- [ ] bitFlyer の CSV（取引履歴）パーサー。今は PDF を Claude が台帳化するだけ。
- [ ] GMO コイン、bitbank、SBI VC などの形式。
- [ ] 時価の取得補助（交換業者の公開 API から取引時点の価格を取り、出典つきで note に書く）。計算エンジンには入れず、取込み側の機能にする。
- [ ] PyPI に公開（`pipx install kakutei-crypto`）。
- [ ] 国税庁の「暗号資産の計算書」Excel の様式そのままに出力する。
- [ ] 対象外の取引（証拠金・CFD・DeFi・NFT・海外交換業者）への段階的な対応。証拠金は損益を別欄にするだけなので比較的簡単。
